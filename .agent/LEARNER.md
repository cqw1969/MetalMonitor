# LEARNER

## 已掌握
- DI 容器构造函数选择规则（贪心选参数最多且可解析的 public 构造函数；internal 不参与）
- readonly 字段只能在构造函数体内赋值（CS0191）
- 能力维度（IsAvailable）与状态维度（IsConnected）的区分

- 对静默行为的敏感度（主动要求全部显式化）
- 跨端复用与分层归属判断（Core 准入两问：它引用了谁？谁消费它？）
- 架构健康自查意识（不凭感觉，凭可检查的不变量：依赖方向/ADR 覆盖/测试网）

## 易混淆点
- "可空参数本身有问题"❌ → 正确理解：可空参数只在暴露给 DI 的 public 构造函数上有害，internal 测试构造函数可用（用户本人澄清）

## 已展现的良好判断
- 2026-10-22 sealed 决策（D-7）：主动识别"约束的价值在模块定稿时最高，开发期最低"，并以"排斥批量机械改动"的变更成本直觉选择最小闭环方案——时机判断成立，记录备查
- 2026-10-23 BoundedObservableCollection 归属复盘（D-6 后）：决策落地后主动用"换 Web 端还能不能用"压力测试自己的决定——用假想消费者检验归属，是架构审查的正确动作；结论：依赖方向未违反，类型不可复用但规则可复用，维持 D-6 不拆分
- 2026-10-27 反向运用"await 让出线程"模型，抓出重连讲解中"心跳排队/线程被占"的机理错误——两个子判断（Timer 不排队、await 不占线程）均成立；漏看的点：调用链上游还有第二把防重入锁 `_isUpdating`，await 让得出线程但让不出"逻辑上一拍"。说明 await 心智模型已稳固到能当尺子用，下一步要补的直觉是"沿调用链找全所有锁，下游锁救不了上游"

## 已掌握（2026-10-27 追加）
- 防重入旗标的保护范围 = 所在方法体的"逻辑上一拍"，与线程占用无关；await 链上挂长任务会抵押旗标
- System.Timers.Timer 到期并发触发，从不排队（AutoReset=true 时上一拍未完则另借池线程）
- await 只能写在 async 方法体内；属性 setter 与构造函数结构上不可 async，异步工作须挪到能 await 的生命周期入口（2026-10-28）

## 学习策略（2026-10-28）
- 用户反馈：常被细节绊住，分不清"是否重要/收益/复用性"，久久不懂时不知如何处置；担心项目变大后技术债失控
- 给出的分诊三问：① 不懂它当前这步能走对吗 ② 错了会大声报错还是沉默地坏 ③ 有无现成约定可照抄——照抄即正确时不必懂原理
- 技术债二分法：死债（修复成本恒定，如废纸代码/命名——可随手记候选后拖）vs 会发酵的债（成本随时间翻倍：核心路径无测试、全局状态、数据结构选错——当场处理）；本项目的保险 = 测试网 + ADR 退场条件 + ARCHITECTURE 地图
- 卡住的标准动作：标记待补 → 继续主线；已有成功先例（await 模型隔两天反用抓出讲解错误）
