# LEARNER

## 已掌握
- DI 容器构造函数选择规则（贪心选参数最多且可解析的 public 构造函数；internal 不参与）
- readonly 字段只能在构造函数体内赋值（CS0191）
- 能力维度（IsAvailable）与状态维度（IsConnected）的区分

## 正在建立
- 多文件项目的架构直觉（能识别构造函数族是"约定"而非"契约"）
- 对静默行为的敏感度（主动要求全部显式化）
- 跨端复用与分层归属判断（Core 准入两问：它引用了谁？谁消费它？）
- 架构健康自查意识（不凭感觉，凭可检查的不变量：依赖方向/ADR 覆盖/测试网）

## 易混淆点
- "可空参数本身有问题"❌ → 正确理解：可空参数只在暴露给 DI 的 public 构造函数上有害，internal 测试构造函数可用（用户本人澄清）

## 已展现的良好判断
- 2026-10-22 sealed 决策（D-7）：主动识别"约束的价值在模块定稿时最高，开发期最低"，并以"排斥批量机械改动"的变更成本直觉选择最小闭环方案——时机判断成立，记录备查
- 2026-10-23 BoundedObservableCollection 归属复盘（D-6 后）：决策落地后主动用"换 Web 端还能不能用"压力测试自己的决定——用假想消费者检验归属，是架构审查的正确动作；结论：依赖方向未违反，类型不可复用但规则可复用，维持 D-6 不拆分
